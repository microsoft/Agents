# Deploy the .NET production reference

Install .NET 10, PowerShell and Azure CLI/Bicep. Use an account allowed to
create App Service, Azure Bot/Web Chat, identity, storage, monitoring and RBAC.
Select the intended Azure public-cloud subscription/tenant first.

## Build and provision

Install packages and run the checks from README.md, then from this directory:

`appsettings.json` contains the production configuration structure. Supply identity,
storage and monitoring values through Azure App Service settings, which override
JSON configuration. The local `appsettings.Development.json` is excluded from the
published artifact; the development launch profile is only used by `dotnet run`.

```powershell
dotnet test tests/ProductionReference.Tests.csproj -p:RestoreConfigFile=NuGet.Config
dotnet publish -c Release -o artifacts/publish -p:RestoreConfigFile=NuGet.Config
Compress-Archive -Path artifacts/publish/* -DestinationPath artifacts/app.zip -Force
az bicep build --file infra/main.bicep
az group create --name <resource-group> --location <region>
az deployment group create --resource-group <resource-group> --name <deployment-name> --template-file infra/main.bicep --parameters appName=<unique-name> location=<region>
```

Preserve publish artifact hashes and resolved NuGet package versions with each
deployment. The SDK baseline is the released Microsoft.Agents packages `1.8.77`.

The language wrapper uses [shared infrastructure](../../shared/production-reference/infra/main.bicep).
Choose globally unique names producing a valid storage account name (letters and
digits, 3–24 characters after removing hyphens and adding `st`). Select
`botSkuName=S1` when required for the intended traffic profile.

The template creates Linux .NET 10 App Service, Azure Bot Web Chat, a user-assigned
managed identity, Blob state and monitoring. The startup command is
`dotnet ProductionReference.dll`; `ASPNETCORE_URLS=http://0.0.0.0:8080` sets the
container-facing listener explicitly. Remote build is disabled because the
artifact already contains the compiled application and SDK package dependencies.

Production settings are generated by Bicep:

```text
APP_ENV=production
Connections__ServiceConnection__Settings__ClientId=<user-assigned identity client ID>
Connections__ServiceConnection__Settings__TenantId=<identity tenant ID>
Storage__ServiceUrl=https://<account>.blob.core.windows.net/
Storage__Container=agents-production-reference-state
APPLICATIONINSIGHTS_CONNECTION_STRING=<monitor connection string>
ASPNETCORE_URLS=http://0.0.0.0:8080
SCM_DO_BUILD_DURING_DEPLOYMENT=false
```

Do not configure local client secrets or storage connection strings. The host
validates the native SDK connection settings before registering the connection.

## Deploy and verify

Use the `webAppName` output:

```powershell
az webapp deploy --resource-group <resource-group> --name <web-app-name>-app --src-path artifacts/app.zip --type zip
python ../../shared/production-reference/scripts/smoke-test.py https://<web-app-name>.azurewebsites.net
```

After deployment and RBAC propagation, use Test in Web Chat for the summary/impact
flow. Verify restart and replica recovery, conflicting writes, real authentication
metadata, channel delivery, telemetry and shutdown. Follow [the runbook](RUNBOOK.md)
for the complete evidence checklist.

Liveness is the App Service health check; monitor storage-dependent readiness
separately. Caller-aware edge protection and origin-bypass prevention, alert rules
and action groups, retention/deletion, and backups are required environment work
outside the supplied infrastructure. TestServer results do not verify those controls.

## Rollback

Retain the previous immutable publish ZIP. Redeploy it with `az webapp deploy`,
rerun smoke/Web Chat/state recovery checks and record rollback time. Keep state
readers compatible with the deployed schema. Do not replace a retained artifact
with a newly rebuilt dependency graph during rollback.
